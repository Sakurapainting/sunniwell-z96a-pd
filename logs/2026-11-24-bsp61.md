# 2026-11-24 · Z96A BSP 6.1 调试

设备为 Sunniwell Z96A（RK3568）。本次实验涉及 mainline `7.2.10-1-aarch64-ARCH`、Rockchip BSP `6.1.172-2-z96a-bsp61` 和为 BSP 包 `6.1.172-3` 准备的补丁。以下为当天的观察和脱敏摘录。

## Mainline 回退与启动文件

- UART 捕获 U-Boot 输出后，通过 U-Boot 手动启动 `linux` 条目并到达 mainline 串口登录。
- 验证了安装 `6.1.172-2` 时的启动文件隔离。BSP 的 Image、DTB 和 initramfs 部署到独立路径，mainline 的三份文件与记录的哈希一致。
- 19:02 的预检仍显示 extlinux 默认条目为 `linux`，设备正在运行 `6.1.172-2-z96a-bsp61`。当次检查 `/boot` 可用 `13,931,520` 字节，后续部署需重新读取余量。

## VOP 时钟与启动失败

`6.1.172-2` 首次使用包内 DTB 启动时，VOP 的 `assigned-clock-rates` 将 VPLL 和 DCLK_VOP1 请求为 132 MHz。DRM 初始化遇到 PLL 锁定超时，重试期间发生内核栈溢出，启动在挂载根文件系统前中止。

```text
[  839.109236] rockchip_rk3036_pll_wait_lock: timeout waiting for pll to lock
[  839.355517] Kernel panic - not syncing: kernel stack overflow
```

随后沿用同一份 Image 和 initramfs，改用仅移除 VOP `assigned-clock-rates` 的诊断 DTB。VOP 和 HDMI DRM 组件完成绑定，根文件系统挂载成功，串口可登录且 systemd 为 `running`。DRM 日志行省略了内核指针。

```text
[   36.253043] rockchip-drm display-subsystem: bound fe040000.vop
[   36.259892] rockchip-drm display-subsystem: bound fe0a0000.hdmi
[   39.234536] EXT4-fs (mmcblk0p10): mounted filesystem with ordered data mode. Quota mode: disabled.
```

## RK809 时钟与 SDIO

诊断启动后，`sdio-pwrseq` 和 `fe2c0000.mmc` 仍在等待依赖。RK809 MFD 产生的 `rk817-clkout` 未匹配到 BSP 的 `rk808-clkout` 驱动。临时绑定后，`sdio-pwrseq` 获得 32.768 kHz 时钟，MMC 主机枚举到 `024C:C822`（RTL8822CS）。测试结束时只有回环网络接口。

```text
modalias=platform:rk817-clkout
driver_before=unbound
bind_status=0
[ 1192.136527] mmc1: new high speed SDIO card at address 0001
SDIO_ID=024C:C822
MODALIAS=sdio:c07v024CdC822
```

## 待验证

`6.1.172-3` 合并了 VOP DTB 调整和时钟驱动匹配补丁。需要用该版本复测自动绑定、串口启动、SDIO 枚举和实体 HDMI 输出。RTL8822CS 驱动支持和 Wi-Fi 连通性仍待验证。NPU 在本次测试中保持禁用，后续上板前需核对 PMIC 与 NPU 供电。 [对应打包提交](https://github.com/Sakurapainting/PKGBUILDs/commit/9b44cb26579194c644aa7ca959c3549717f969c5)
